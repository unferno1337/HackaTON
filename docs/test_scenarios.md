# CampusPulse AI — тестовые сценарии

Демо-данные: 3 курса, 5 событий, 5 локаций.
Дедлайны и события заданы относительными оффсетами, поэтому
сценарии воспроизводимы в любой день.

## 1. Дедлайн-триаж

Вход: «Что у меня горит на этой неделе?»

Ожидаемые вызовы: get_deadlines с окном 7 дней.

Ожидаемый ответ: 1–3 пункта, ближайший — Lab 4: Raft consensus,
затем Assignment 3: CNN classifier. Для каждого: курс, срок,
вес, следующий шаг. Источники: campuspulse://courses.

Критерий прохождения: все сроки и веса совпадают с tool output.

## 2. Тихое место с кофе и розеткой

Вход: «Нужно тихое место с кофе и розеткой недалеко от меня.»

Ожидаемые вызовы: find_study_spot с features
silent, coffee, power и open_now=true.

Ожидаемый ответ: Campus Hub Co-working или Atrium Cafe,
почему подходит, часы работы, сколько идти. Если место закрыто,
агент не должен писать «открыто сейчас».

Критерий прохождения: в ответе есть только места из tool output,
open_now не выдуман.

## 3. Событие по AI

Вход: «Куда сходить по AI на этой неделе?»

Ожидаемые вызовы: search_events с query AI и окном 7 дней.

Ожидаемый ответ: GDG Astana: AI Night и Robotics Demo Day,
дата, время, место, одна причина пойти.

Критерий прохождения: совпадение с events.json, source
campuspulse://events, нет несуществующих событий.

## 4. План подготовки к двум дедлайнам

Вход: «Успею ли подготовить Raft и CNN? Составь план.»

Ожидаемые вызовы: get_deadlines по обоим курсам,
find_study_spot с silent и power.

Ожидаемый ответ: порядок работ, ориентировочные блоки времени,
место для подготовки, честный вывод о рисках. Если времени
мало, агент говорит это прямо, а не обещает невозможное.

Критерий прохождения: план опирается на реальные дедлайны
из tool output; время на посещение и подготовку реалистично.

## 5. Недостающие данные

Вход: «Где ближайшая аптека?»

Ожидаемые вызовы: поиск по локациям не даёт аптек.

Ожидаемый ответ: «В данных кампуса нет аптек» плюс,
если уместно, ближайшие доступные категории из tool output.

Критерий прохождения: нет выдуманной аптеки, нет выдуманного
адреса, явно сказано, чего не хватает.

## Ограничения

- Данные синтетические.
- Нет live-загруженности и погоды.
- Время работы статичное, без праздников.
- Нет геолокации: пользователь сам сообщает контекст.
- Модель может ошибаться; источники и трейс нужны для проверки.
- В демо нет авторизации и ограничения запросов.
